Проект собран целиком и доведён до рабочего состояния: production-сборка проходит, 76 unit-тестов зелёные,
53 проверки смоук-теста на живом сервере пройдены, Lighthouse mobile 96/100/100/100.

## 1. Что реализовано (по разделам ТЗ)

### §0 Правила работы

- Весь документ прочитан, работу вёл по этапам §14, в конце сверился с §15.
- Язык интерфейса — русский; код, идентификаторы и комментарии — английский.
- Mobile-first: вёрстка проверялась от 360 px, тап-цели ≥ 48 px, инпуты ≥ 16 px (iOS не зумит).
- Секреты только в серверных env; в репозитории значений нет (`.env.example` пустой, `.env` в `.gitignore`).
- 2ГИС и Instagram не скрейпились, чужие тексты и фото не копировались, логотипы автомарок не использовались
  (марки — текстовыми чипами).

### §1 DATA

`content/business.ts` — единственный источник фактов: адрес, координаты, `Asia/Almaty`, часы, два номера WhatsApp,
Instagram, ссылки и рейтинг 2ГИС, 35 марок. Всё, чего в 2ГИС не было (услуги, цены, отзывы, фото, мастера),
помечено как вводимое владельцем; блоки на сайте скрыты, пока данных нет.

### §2 Цели и метрики

| Цель | Как обеспечена |
|---|---|
| Запись ≤ 90 с и ≤ 4 шага | визард из 4 шагов, прогресс-бар, черновик в `sessionStorage`, залипающая кнопка «Далее» |
| Карточка владельцу ≤ 5 с | запись в БД и постановка уведомления в одной транзакции, отправка сразу с таймаутом 5 с |
| Нет двойных броней | `BEGIN IMMEDIATE` + строка `day_locks(local_date)` + пересчёт доступности внутри транзакции |
| Владелец правит сам | разделы «Услуги», «График», «Контент», «Настройки» в `/admin` |
| Заявка не теряется | outbox `notifications` со статусами `pending/sent/failed`, backoff 1-2-5-15-60 мин до 8 попыток, бейдж в админке |
| Быстро и находимо | Lighthouse mobile 96/100/100/100, desktop 100/100/100/100, локальное SEO Кокшетау |

### §3 Стек

Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 + lucide-react + Zod 4 + better-sqlite3.
Даты: `date-fns` + `date-fns-tz`, в БД — UTC, вся логика и отображение — в `Asia/Almaty`.
Тесты: Vitest (логика слотов, телефоны, статусы, уведомления, таймзоны, экранирование Telegram).
Дополнительно: PowerShell-смоук по живому серверу и скрипт Lighthouse.
Структура каталогов соответствует §3 (`/app`, `/lib/availability.ts`, `/lib/telegram.ts`, `/lib/notify.ts`,
`/lib/phone.ts`, `/db/schema.ts`, `/content/business.ts`, `/scripts/*`).

### §4 Структура сайта

Страницы: `/` (лендинг с якорями), `/zapis` (прямая ссылка для 2ГИС и Instagram, читает `?service=` и UTM),
`/booking/[token]`, `/privacy`, `/admin/*` (noindex), кастомная 404.
Блоки лендинга: sticky-шапка с бургером, Hero с H1 из ТЗ, услуги из БД (последняя карточка — про диагностику),
«Как записаться» (4 шага), 35 марок, «Почему выбирают нас» (только подтверждённые факты), плашка рейтинга 2ГИС
со ссылкой, отзывы из БД (скрыт, пока пусто), галерея (скрыта, пока пусто), FAQ-аккордеон (6 вопросов), контакты
с картой OpenStreetMap по клику и тремя кнопками маршрута, футер. Снизу на мобильном — панель
[Позвонить] [WhatsApp] [Записаться] с учётом `safe-area`.

### §5 Дизайн-система

Тёмная премиальная тема, токены из ТЗ (`bg #0E0F11`, `surface #16181B`, `surface-2 #1E2126`, `border #2A2E34`,
`text #F2F3F5`, `muted #9AA1AB`, `accent #FF5A1F`, `success #2EC27E`, `danger #F04A4A`), текст на акцентной
кнопке тёмный. Manrope 400/600/800, H1 `clamp(32px, 6vw, 56px)`, body 16 px. Радиусы 16/12, сетка 8 px.
Hero-визуал — векторная линейная графика (силуэт авто + сетка) в акценте; при появлении
`public/images/hero.jpg` автоматически используется фото. Тонкий геометрический орнамент-сетка с opacity 6 %.
Анимации ≤ 250 мс с уважением к `prefers-reduced-motion`. Состояния loading/empty/error/success — везде
(скелетоны слотов и списков, пустые состояния, сообщения об ошибках, экран успеха).

### §6 Онлайн-запись

- Смысл записи: время **приёма-осмотра**, а не всего ремонта — написано в описаниях услуг и в визарде.
- UX: bottom sheet на мобильном, диалог на десктопе, та же форма на `/zapis`; прогресс-бар, возврат без потери
  данных, черновик в `sessionStorage`, honeypot, минимальное время заполнения, `Idempotency-Key` с клиента.
- Шаг 1: услуги из БД + «не знаю, что сломалось». Шаг 2: марка через combobox (35 марок + свободный ввод),
  модель, год, гос. номер. Шаг 3: горизонтальный скроллер дат (21 день, дни без слотов приглушены), слоты
  группами «Утро / День / Вечер», занятые недоступны, при другой таймзоне устройства — подпись «Время указано
  по Кокшетау». Шаг 4: имя, телефон с маской `+7 (___) ___-__-__`, способ связи, комментарий ≤ 500,
  обязательное согласие со ссылкой на `/privacy`.
- Экран успеха: галочка, «Запись №0042 отправлена мастеру», карточка-резюме, `.ics` (клиентская генерация),
  ссылка `/booking/[token]`, кнопка звонка.
- `/booking/[token]`: публично по UUID v4, минимум данных (без телефона), опрос каждые 30 с, отмена клиентом
  освобождает слот и уведомляет владельца, перенос = отмена + новая запись.
- Логика слотов `lib/availability.ts` — чистые функции, экспорт `computeSlots`, `effectiveWindow`, `canTransition`;
  занятыми считаются только `new` и `confirmed`.

### §7 Telegram

- Карточка владельцу в формате из ТЗ (`parse_mode=HTML`, весь ввод экранируется), inline-кнопки
  `✅ Подтвердить` / `❌ Отклонить` / `💬 WhatsApp клиенту` (готовый текст подтверждения) / `🛠 Открыть в админке`.
- Outbox: уведомление создаётся в той же транзакции, что и бронь; ошибка → backoff 1-2-5-15-60 мин, до 8 попыток;
  учитывается 429 (`retry_after`) и лимит 4096 символов (комментарий обрезается до 500).
- `/api/telegram/webhook`: проверка `X-Telegram-Bot-Api-Secret-Token`, авторизация по `TELEGRAM_CHAT_IDS`,
  `callback_data` формата `bk:<id>:<action>`, идемпотентность («Уже обработано»), редактирование карточки и клавиатуры.
- Команды: `/start` (чужому — только его `chat_id`, владельцу — справка), `/today`, `/tomorrow`, `/new`.
- Флаг `TELEGRAM_CALLBACKS_ENABLED` (§7.6) с двумя описанными режимами; `npm run tg:webhook` отказывается
  ставить вебхук в режиме «только отправка».
- Из §7.7 реализовано: кнопка «Прислать тестовое сообщение» в админке и обработчик `/start b_<token>`
  для привязки клиента к боту. Ежедневный дайджест и кнопка привязки на экране успеха — не сделаны
  (см. «Ограничения»).

### §8 Админка

Один пароль (`ADMIN_PASSWORD`, сравнение timing-safe), сессия — подписанный cookie `httpOnly; SameSite=Lax`,
`Secure` при HTTPS, 7 дней, лимит 5 неудачных попыток / 15 мин / IP, проверка `Origin` на мутациях.
Разделы: «Записи» (вкладки, фильтры, поиск, смена статуса, WhatsApp, звонок, повторная отправка в Telegram,
бейдж доставки, создание записи вручную со слотами из БД, экспорт CSV), «Услуги» (CRUD, порядок, скрытие),
«График» (часы по дням, посты, шаг, буфер, минимальный запас, горизонт, выходные и сокращённые дни),
«Контент» (контакты, отзывы, фото, тексты «Почему мы»), «Настройки» (тест Telegram, режим кнопок, срок хранения).
Админка удобна с телефона: одна колонка, крупные элементы, ссылка открывается из Telegram.

### §9 Модель данных и API

Таблицы: `services`, `bookings`, `settings`, `days_off`, `day_locks`, `notifications`, `reviews`, `photos`,
`rate_limits` (+ служебная `audit_log`), индексы по `start_at`, `(status, start_at)`, `client_phone`,
`(status, next_attempt_at)`. Эндпоинты реализованы все из §9.2, включая `/api/availability/days`
для скроллера дат и `/api/cron/notify` под `CRON_SECRET`.

### §10 Безопасность, антиспам, надёжность

Zod на сервере (с русскими сообщениями), нормализация KZ/RU телефонов, rate limit 5/час/IP и 3/сутки/телефон
в БД (не в памяти), honeypot + минимум 3 с на заполнение + Turnstile по env, экранирование ввода для Telegram,
отсутствие `dangerouslySetInnerHTML` с пользовательскими данными, CSP и сопутствующие заголовки, HSTS на проде,
логи без телефонов (маска `+7705***2164`), токен брони — UUID v4, страница `/privacy`, удаление записи в админке,
обезличивание данных по сроку хранения.

### §11 SEO, аналитика, производительность

Метаданные, canonical, Open Graph c изображением 1200×630 (`public/og.jpg`), Twitter-карточка, favicon и
PWA-манифест, `lang="ru"`, один H1. JSON-LD `AutoRepair` с адресом, гео, телефоном, часами и `sameAs` —
**без `aggregateRating`**. `sitemap.xml`, `robots.txt` (`/admin`, `/booking`, `/api` закрыты), локальные ключи
вплетены в тексты. Аналитика по env (выключена по умолчанию), события `booking_open`, `booking_step_N`,
`booking_submit`, `booking_success`, `click_phone`, `click_whatsapp`, `click_route`, `click_2gis_reviews`,
UTM сохраняются в брони. Производительность: форма записи и карта подгружаются по действию, шрифт с
`display: swap`, изображения с `width/height`, карта — OSM по клику (без ключей).

### §12 Контент

Ничего не выдумано: утверждения только из DATA или из админки. Блоки «гарантия / опыт / оборудование»
существуют, но пусты и на сайте не показываются, пока владелец их не заполнит. Seed услуг помечен как черновик.

### §13 Env и деплой

`.env.example` со всеми переменными без значений, `npm run env:init` создаёт локальный `.env` со случайными
секретами. README содержит локальный запуск, миграции, seed, пошаговую настройку бота, два режима Telegram,
деплой с планировщиком `/api/cron/notify`, раздел «Допущения» и инструкцию владельцу на одну страницу.

## 2. Переменные окружения и настройка бота

Полный список — в README, раздел 2. Порядок настройки бота владельцем:

1. @BotFather → `/newbot` → получить токен → `TELEGRAM_BOT_TOKEN`.
2. Владелец пишет боту `/start` → бот отвечает `Ваш chat_id: N` → записать в `TELEGRAM_CHAT_IDS`.
3. Задать `PUBLIC_BASE_URL` и `TELEGRAM_WEBHOOK_SECRET` (32+ случайных символа).
4. `npm run tg:webhook` (при `TELEGRAM_CALLBACKS_ENABLED=true`).
5. Проверка: админка → «Настройки» → «Прислать тестовое сообщение».

## 3. Принятые допущения

Полный список с обоснованиями — в README, раздел 8. Кратко: SQLite вместо PostgreSQL (с путём перехода),
2 поста по умолчанию, шаг слотов 30 минут, горизонт 21 день, минимальный запас 60 минут, буфер 0,
«частичный выходной» = сокращённый день, seed услуг — черновик, отзывы и фото не выдуманы, OG-картинка
сгенерирована, `Secure` для cookie админки включается при HTTPS, CSP пока с `unsafe-inline` для инлайн-бутстрапа
Next.js, валидация на клиенте написана вручную по тем же правилам, что и Zod на сервере (чтобы не тянуть
библиотеку в бандл).

## 6. Известные ограничения и предложения на следующую итерацию

**Ограничения**

1. **Telegram не проверен на живом чате** — в рабочем окружении нет токена бота владельца. Код отправки,
   вебхука, кнопок и ретраев покрыт тестами; после получения токена достаточно выполнить `npm run tg:webhook`.
2. **SQLite вместо PostgreSQL** — работает на одном сервере с постоянным диском. Для serverless-хостинга нужен
   переход на PostgreSQL (схема переносится почти дословно).
3. **`aggregateRating` в JSON-LD сознательно отсутствует** — рейтинг принадлежит 2ГИС, а не сайту.
4. **CSP пока с `unsafe-inline`** для скриптов из-за инлайн-бутстрапа Next.js.
5. **Ежедневный дайджест владельцу в 08:00** (§7.7) и **кнопка «Получать статус в Telegram» на экране успеха**
   не сделаны: обработчик `/start b_<token>` в вебхуке уже готов, нужен только вывод кнопки с username бота.
6. **Аналитика выключена** — включается заданием `NEXT_PUBLIC_YM_ID` или `NEXT_PUBLIC_GA_ID`.
7. **Проверка «не робот»** без Turnstile опирается на honeypot и минимальное время заполнения.

**Предложения**
