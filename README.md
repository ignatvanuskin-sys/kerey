# Керей — автокомплекс в Кокшетау

Сайт автосервиса с онлайн-записью, карточкой клиента в Telegram и админкой для владельца.
Стек: Next.js (App Router) + TypeScript + Tailwind CSS + SQLite (better-sqlite3) + Telegram Bot API.

Что уже работает:

- лендинг на русском, mobile-first (360 px → 1440 px), тёмная тема, дизайн-токены из ТЗ;
- отдельная страница записи `/zapis` и визард записи в 4 шага (bottom sheet на телефоне, диалог на десктопе);
- расчёт свободного времени по постам, буферу и времени приёма; защита от двойных броней;
- карточка клиента в Telegram с кнопками «Подтвердить» / «Отклонить», повторные попытки отправки;
- страница статуса записи `/booking/[token]` с опросом каждые 30 секунд и отменой клиентом;
- админка `/admin`: записи, услуги, график, выходные, контент, тесты Telegram;
- SEO (JSON-LD `AutoRepair`, sitemap, robots), аналитика по env, политика конфиденциальности.

## 1. Локальный запуск

Нужен Node.js 20+ (проверено на 22).

```bash
npm install
npm run env:init        # создаст .env со случайными паролями (файл в .gitignore)
npm run db:migrate      # создаст базу и таблицы
npm run db:seed         # черновой список услуг + настройки по умолчанию
npm run dev             # http://localhost:3000
```

Админка: http://localhost:3000/admin — пароль в `.env`, строка `ADMIN_PASSWORD` (её печатает `env:init`).

Продакшн-сборка:

```bash
npm run build
npm run start
```

Полезные команды:

| Команда | Что делает |
|---|---|
| `npm run db:migrate` | применяет схему (безопасно запускать повторно) |
| `npm run db:reset` | удаляет файл базы и создаёт пустую схему |
| `npm run db:seed` | добавляет черновые услуги, не перезаписывая уже изменённые |
| `npm run db:clear-limits` | сбрасывает счётчики антиспама (5 записей в час с адреса, попытки входа) |
| `npm run lighthouse` | снимает Lighthouse mobile + desktop, отчёты в `data/` |
| `npm run og:make` | пересобирает картинку для соцсетей 1200×630 из исходника |
| `npm test` | Vitest: логика слотов, телефоны, статусы, уведомления, горизонт записи |
| `npm run smoke` | поднимает сервер и прогоняет 50+ проверок API и страниц |
| `npm run tg:webhook` / `tg:webhook:info` / `tg:webhook:delete` | управление вебхуком Telegram |
| `npm run cron:notify` | локально обработать очередь уведомлений |
| `npm run typecheck` | проверка типов |

## 2. Переменные окружения

Скопируйте `.env.example` в `.env` (или запустите `npm run env:init`).

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да | `file:./data/kerey.db` — путь к файлу базы |
| `PUBLIC_BASE_URL` | да | публичный адрес сайта без слэша на конце (ссылки в Telegram, sitemap, вебхук) |
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_CHAT_IDS` | да | получатели карточек через запятую (личный chat_id и/или группа) |
| `TELEGRAM_WEBHOOK_SECRET` | да | случайная строка 32+ символов для защиты вебхука |
| `TELEGRAM_CALLBACKS_ENABLED` | нет | `true` (по умолчанию) — сайт обрабатывает кнопки ✅/❌ |
| `TELEGRAM_BOT_USERNAME` | нет | username бота без @ |
| `ADMIN_PASSWORD` | да | пароль входа в админку |
| `SESSION_SECRET` | да | подпись cookie сессии администратора |
| `CRON_SECRET` | да | ключ для `/api/cron/notify` |
| `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | нет | Cloudflare Turnstile, включается сам, если задан секрет |
| `NEXT_PUBLIC_YM_ID` / `NEXT_PUBLIC_GA_ID` | нет | аналитика; без них не подключается вовсе |

Секреты хранятся только на сервере: в клиентский бандл попадают лишь значения `NEXT_PUBLIC_*`.

## 3. Настройка Telegram-бота (для владельца)

1. Владелец открывает в Telegram **@BotFather** → команда `/newbot` → задаёт имя и username бота.
2. BotFather присылает **токен** вида `123456:AA...` — вставить его в `TELEGRAM_BOT_TOKEN`.
3. Владелец открывает своего бота и нажимает **Start** (отправляет `/start`).
4. Бот отвечает: `Ваш chat_id: 123456789. Передайте его владельцу` — этот номер записать в `TELEGRAM_CHAT_IDS`.
   Можно добавить несколько получателей через запятую: личный чат + группа администраторов.
   Для группы: добавьте бота в группу и получите её `chat_id` (у групп он отрицательный, начинается с `-100`).
5. Задать `PUBLIC_BASE_URL` (адрес сайта) и `TELEGRAM_WEBHOOK_SECRET` (случайная строка 32+ символа).
6. Установить вебхук: `npm run tg:webhook`.
7. Проверить в админке → «Настройки» → «Прислать тестовое сообщение».

После этого каждая новая запись с сайта приходит карточкой с кнопками **✅ Подтвердить** и **❌ Отклонить**.
Нажатие меняет статус на сайте, а кнопка «💬 WhatsApp клиенту» открывает чат с готовым текстом подтверждения.

## 4. Два режима Telegram

| Режим | Когда использовать | Как включить |
|---|---|---|
| **Кнопки в Telegram** (по умолчанию) | у бота нет других задач | `TELEGRAM_CALLBACKS_ENABLED=true` + `npm run tg:webhook` |
| **Только отправка карточек** | бот уже получает сообщения в другом сервисе (свой webhook или polling) | `TELEGRAM_CALLBACKS_ENABLED=false` — вебхук не ставим, статусы меняются в админке |

Telegram разрешает только один способ получения обновлений: если бот занят другим сервисом, вебхук ставить нельзя —
`npm run tg:webhook` в этом случае откажется работать и объяснит причину. Карточки всё равно будут приходить,
но кнопки будут вести в WhatsApp и админку, а не менять статус напрямую.

## 5. Админка: что где лежит

- **Записи** — вкладки «Сегодня / Завтра / Новые / Все», фильтры по статусу, дате и поиск, смена статуса,
  кнопки «Позвонить» и «WhatsApp», повторная отправка карточки в Telegram, бейдж состояния доставки,
  создание записи вручную (звонок или визит), экспорт CSV.
- **Услуги** — названия, описания, длительность приёма, цена «от» или текст «по результатам диагностики»,
  порядок карточек, скрытие с сайта.
- **График** — часы по дням недели, число постов, шаг слотов, перерыв между записями, минимальный запас времени,
  горизонт записи, выходные и сокращённые дни с причиной.
- **Контент** — контакты (переопределяют данные 2ГИС), отзывы клиентов, фото, тексты «Почему мы».
- **Настройки** — тестовое сообщение в Telegram, режим кнопок, срок хранения персональных данных.

## 6. Деплой

Сайт — обычное Next.js приложение. Нужен постоянный диск для файла базы (SQLite).

1. Соберите проект: `npm run build`.
2. Задайте переменные окружения из раздела 2 (значения — продакшн).
3. Запустите `npm run start` (порт по умолчанию 3000) за обратным прокси с HTTPS.
4. Планировщик: раз в 1–5 минут вызывать

   ```
   GET https://<ваш-домен>/api/cron/notify?secret=<CRON_SECRET>
   ```

   Это повторная отправка недоставленных карточек в Telegram и обезличивание старых персональных данных.
   Вместо планировщика можно держать отдельный процесс `npm run cron:notify`.
5. После смены домена обновите `PUBLIC_BASE_URL` и заново выполните `npm run tg:webhook`.

Вебхук Telegram работает на любой платформе, отдающей `/api/telegram/webhook` по HTTPS.
Для serverless-платформ без постоянного диска нужен переход на PostgreSQL (см. «Допущения») и очередь уведомлений
через внешний планировщик — это отдельная итерация.

## 8. Допущения

Всё, что не было задано в ТЗ, решено так (можно изменить без переписывания кода):

1. **База — SQLite** (файл `data/kerey.db`) вместо PostgreSQL: разворачивается без внешних сервисов, транзакции
   атомарны (`BEGIN IMMEDIATE` + блокировка дня). Переход на PostgreSQL: схема из `db/schema.ts` переносится
   почти дословно (`timestamptz` вместо строк ISO), меняются `db/client.ts` и запросы.
2. **Постов по умолчанию 2** — правится в админке («График → Ёмкость»). Точно число постов владелец не подтверждал.
3. **Шаг слотов 30 минут, горизонт записи 21 день, минимальный запас 60 минут, перерыв между записями 0.**
4. **Длительность в записи — время приёма-осмотра**, а не всего ремонта; это написано в описаниях услуг и в визарде.
5. **Частичный выходной = сокращённый день**: запись `days_off` с полями «Открытие с» / «Закрытие в» сужает окно
   приёма, без них день закрыт полностью.
6. **Список услуг — черновик** (§12 ТЗ): владелец обязан проверить названия, длительность и цены.
   Цены пустые — на сайте показывается «по результатам диагностики».
7. **Рейтинг 4,9 публикуется со ссылкой на 2ГИС** и без `aggregateRating` в разметке: это внешние отзывы, а не
   собственные. Тексты отзывов и фото не выдуманы — блоки появятся, когда владелец добавит их в админке.
8. **Фото и отзывы не скрейпились** из 2ГИС и Instagram: пустые блоки скрыты.
9. **Файлы фотографий** загружаются на сервер вручную в `public/images/`, в админке указывается путь (`/images/ceh.jpg`)
   или ссылка. Фото с именем `hero.jpg` в `public/images/` автоматически заменяет векторную графику в шапке.
10. **OG-картинка** (1200×630, `public/og.jpg`) сгенерирована для соцсетей, исходник — `media-output/`.
11. **Cookie админки** помечается `Secure` только когда `PUBLIC_BASE_URL` начинается с `https://`.
12. **CSP** разрешает `unsafe-inline` для скриптов (инлайн-бутстрап Next.js). Переход на nonce — следующая итерация.
13. **Шрифт Manrope** подключается через `next/font` (self-hosting при сборке), `display: swap`, `preconnect`.
14. **Аналитика выключена по умолчанию**: события отправляются только при заданных `NEXT_PUBLIC_*`.
15. **Политика конфиденциальности** — типовая, перед публикацией её должен проверить юрист; реквизиты оператора
    помечены как `TODO_OWNER`.
16. **Проверка «не робот»** — honeypot + минимальное время заполнения (3 секунды) + Turnstile, если заданы ключи.
17. **UTF-8 без BOM в `.ps1`** не читается PowerShell 5.1 — служебные скрипты сохранены с BOM.

## 9. Инструкция владельцу (одна страница)

**Как приходят записи.** Клиент записывается на сайте → вам сразу приходит сообщение в Telegram с данными:
услуга, машина, дата и время, имя, телефон, комментарий. Под сообщением две кнопки.

- **✅ Подтвердить** — нажимаете, когда согласны на это время. Статус на сайте сразу меняется,
  клиент видит «Подтверждена».
- **❌ Отклонить** — если время не подходит. Слот освобождается, время снова доступно для записи.
- **💬 WhatsApp клиенту** — открывает чат с готовым текстом подтверждения; остаётся нажать «Отправить».
- **🛠 Открыть в админке** — полная карточка записи в браузере.

Дальше, когда клиент приехал или не приехал: **✔️ Выполнено** или **🚫 Не приехал**. Если планы изменились —
**↩️ Отменить**.

Случайное нажатие ничего не сломает: повторное нажатие просто ответит «Уже обработано».

**Как поменять цены, названия и длительность услуг.** Откройте админку → **Услуги**. Можно менять название,
описание, длительность приёма (в минутах), цену «от» (если цены нет — оставьте поле пустым, на сайте напишется
«по результатам диагностики»), порядок карточек кнопками ↑ ↓ и скрыть услугу с сайта переключателем.

**Как изменить часы работы.** Админка → **График**. Для каждого дня недели поставьте галочку «Работаем» и укажите
часы. Снятая галочка = выходной. Ниже — сколько машин вы принимаете одновременно (постов) и другие мелочи:
шаг времени, перерыв между работами, за сколько минут до приёма закрывать запись.

**Выходные и праздники.** Админка → **График** → «Выходные и сокращённые дни»: выберите дату и добавьте её
(например, 1 января, причина «праздник»). Если в этот день работаете меньше — укажите «Открытие с» и «Закрытие в».
Кнопка «Сделать рабочим» возвращает обычный график.

**Как поменять телефон, адрес и WhatsApp.** Админка → **Контент** → «Контакты на сайте». Пустое поле = берётся
значение из карточки 2ГИС.

**Как добавить фото и отзывы.** Админка → **Контент**. Фото сначала положите файлом на сервер (папка `public/images`)
и укажите путь вида `/images/ceh.jpg`. Отзывы — только реальные, со слов клиента. Пока список пуст, блок на сайте
не показывается.

**Если Telegram молчит.** Откройте админку → **Записи**: у записи будет пометка «Telegram не доставлен» и кнопка
«В Telegram повторно». Проверить связь целиком: **Настройки** → «Прислать тестовое сообщение».

**Пароль от админки** задаётся при настройке сайта (`ADMIN_PASSWORD`). Ссылка на админку: `ваш-сайт/admin`.
