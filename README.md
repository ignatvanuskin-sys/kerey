# Керей — автокомплекс в Кокшетау

Продающий сайт с онлайн-записью и панелью заявок для автокомплекса «Керей»
(Кокшетау, улица Шокана Уалиханова, 94).

Стек: **Next.js 16** + **TypeScript** + **Tailwind CSS 4** + **Lucide React**.
Всё содержимое сайта собрано из публичной карточки компании в 2ГИС — выдуманных фактов, цен,
отзывов и фотографий на сайте нет.

| Блок | Описание |

| Услуги | 6 направлений, собранных из рубрик карточки 2ГИС. Цены не выдуманы: везде «Стоимость уточняется» |
| Как записаться | 4 шага процесса |
| Почему мы | 4 факта, которые можно проверить по карточке 2ГИС (без «гарантий качества» и прочих неподтверждённых обещаний) |
| О компании | Короткий текст из подтверждённых данных + галерея |
| Отзывы | 10 реальных отзывов из 2ГИС, включая критические, без правок формулировок |
| Марки | 35 марок из карточки |
| FAQ | 10 вопросов; там, где данных нет, — «уточните у администратора» |
| Контакты | Адрес, остановка, часы, два WhatsApp, Instagram, кнопки «Позвонить» и «Построить маршрут», карта |
| Онлайн-запись | Мастер из 5 шагов, экран подтверждения, проверка занятости времени |
| Панель заявок | `/admin`: счётчики, фильтры, поиск, таблица заявок, смена статуса |

**Онлайн-запись.** Пять шагов: услуга → данные автомобиля → дата → время → контакты.
Свободное время считается по часам работы из карточки 2ГИС (ежедневно 08:30–21:00), шаг 30 минут,
запись открыта на 14 дней вперёд, на один слот — одна заявка (число постов владелец не подтверждал),
закрываем запись за час до приёма — чтобы мастер успел подготовиться.

**Панель заявок.** Адрес `/admin`, вход по паролю из переменной `ADMIN_PASSWORD`.
Статусы: `NEW` → `CONFIRMED` → `COMPLETED`, плюс `CANCELLED`. Заявки сохраняются в
`data/bookings.json` (файл в `.gitignore` — там персональные данные клиентов).

## 2. Быстрый старт

```bash
npm install
npm run env:init      # создаст .env со случайным паролем для /admin
npm run dev           # http://localhost:3000
```

Продакшн:

```bash
npm run build
npm run start
```

Проверки:

```bash
npm run check      # линтер + типы + тесты
npm run smoke      # поднимает собранный сайт и прогоняет 44 проверки страниц, записи и панели
npm run lighthouse # снимает Lighthouse (мобильный и десктопный профили)
```

Служебные команды:

| Команда | Что делает |
|---|---|
| `npm run reset` | удаляет все заявки и обнуляет нумерацию (перед показом владельцу) |
| `npm run env:init` | создаёт `.env` со случайными секретами |
| `npm run make-images` | пересобирает изображения сайта из исходников в `media-output/` |

## 3. Переменные окружения

Скопируйте `.env.example` в `.env` или выполните `npm run env:init`.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `PUBLIC_BASE_URL` | да | публичный адрес сайта без слэша на конце (Open Graph, sitemap) |
| `ADMIN_PASSWORD` | да | пароль для входа в панель заявок |
| `SESSION_SECRET` | да | подпись cookie сессии администратора |
| `TELEGRAM_BOT_TOKEN` | нет | токен бота — если нужно получать заявки в Telegram |
| `TELEGRAM_CHAT_IDS` | нет | получатели заявок через запятую |

Пока Telegram-переменные пустые, заявки просто сохраняются в панели — сайт работает полностью.

## 4. Как подключить Telegram (по желанию)

Уведомления уже реализованы в `lib/telegram.ts`, включаются переменными окружения:

1. Владелец создаёт бота у **@BotFather** (команда `/newbot`) и присылает токен.
2. Токен → в `TELEGRAM_BOT_TOKEN`.
3. Владелец пишет боту `/start`. Чтобы узнать `chat_id`, есть два пути: посмотреть его в настройках
   бота у @BotFather или у любого бота, который показывает ID.
4. `chat_id` → в `TELEGRAM_CHAT_IDS`. Можно несколько получателей через запятую: личный чат и группа.
5. Перезапустить сайт. Новая заявка придёт сообщением с номером, услугой, автомобилем, временем,
   именем и телефоном клиента.

Если уведомление не отправилось, заявка всё равно сохранена в панели — в карточке заявки будет
пометка «Уведомление не отправлено».

## 7. Допущения

Всё, чего не было в карточке 2ГИС, решено явно — не выдумано:

1. **Услуг и цен в карточке нет** (вкладка «Цены» пустая). Каталог собран из дополнительных рубрик
   карточки: ремонт ходовой части, ремонт бензиновых двигателей, развал-схождение, запчасти для
   иномарок. Плюс основная рубрика «Легковой автосервис» и пункт «Не знаю, что сломалось».
   Цены везде «Стоимость уточняется».
2. **Одна заявка на слот.** Сколько машин сервис принимает одновременно, в карточке не указано.
   Чтобы не посадить двух клиентов на одно время, вместимость = 1 (меняется одной константой).
3. **Длительность приёма — 60 минут** (30 для запчастей). Это длина окна в расписании, а не обещание
   длительности ремонта; на сайте прямо сказано, что стоимость и объём работ определяются после осмотра.
4. **Запись открыта на 14 дней** вперёд, не позднее чем за час до приёма.
5. **Изображения — демонстрационные.** В карточке 2ГИС 14 фотографий, но прямых ссылок на файлы
   карточка не отдаёт, скачать их автоматически нельзя. В галерее стоят сгенерированные изображения,
   под галереей это указано. Перед запуском их нужно заменить фотографиями сервиса.
6. **Отзывы приведены как есть**, включая две оценки 1★. Рейтинг 4.9 и число отзывов в разметке
   `LocalBusiness` не указываются как `aggregateRating`: рейтинг принадлежит 2ГИС, а не сайту.
7. **Описание компании, гарантия, прайс, реквизиты** в карточке отсутствуют. Соответствующие поля
   помечены `null` в `content/business.ts`, на сайте вместо них нейтральные формулировки.
8. **Аналитики нет** — счётчики не подключены, чтобы не ставить «мёртвый» код. Подключение Яндекс.Метрики
   или GA — одна вставка скрипта в `app/layout.tsx`.
9. **Хранилище — JSON-файл** (`data/bookings.json`) с атомарной записью и очередью операций.
   Для одного сервера этого достаточно; замена на PostgreSQL или CRM делается внутри `lib/storage.ts`
   без изменений в сервисе заявок.
10. **Панель заявок** защищена одним паролем и лимитом 5 попыток входа за 15 минут с одного адреса.
    Публичная форма защищена лимитом 5 заявок в час с адреса, скрытым полем-приманкой и проверкой
    минимального времени заполнения.

## 8. Деплой

### Обычный сервер (VPS) — самый простой вариант

1. `npm run build` → `npm run start` (по умолчанию порт 3000) за обратным прокси с HTTPS.
2. Задайте переменные окружения из раздела 3 (значения — продакшн).
3. Убедитесь, что каталог `data/` доступен на запись и попадает в резервные копии: там заявки.
4. Панель доступна по адресу `ваш-домен/admin` — ссылку не публикуйте.

Здесь работает файловое хранилище, никаких баз подключать не нужно.

### Vercel

Проект собирается автоматически при пуше в `main`. У Vercel файловая система только для чтения,
поэтому до подключения базы сайт работает в **демонстрационном режиме**: форма записи и панель
работают, но заявки хранятся во временном каталоге и не переживают перезапуск инстанса —
на панели и на экране после записи об этом прямо написано.

Порядок действий, чтобы включить рабочий режим:

1. **Хранилище заявок.** В проекте: **Storage → Create Database → Upstash Redis** (есть бесплатный
   тариф) → **Connect** к проекту. Vercel сам добавит переменные `KV_REST_API_URL` и
   `KV_REST_API_TOKEN` → **Redeploy**. Демонстрационный режим выключится автоматически.
2. **Доступ к панели.** **Settings → Environment Variables**: `ADMIN_PASSWORD` (пароль владельца)
   и `SESSION_SECRET` (случайные 32+ символа) → **Redeploy**. До этого панель открывается
   демонстрационным паролем `demo`, который перестаёт работать сразу после установки своего.

> **Важно.** Пока база не подключена, не давайте ссылку на Vercel в рекламу: заявки из неё
> не сохраняются. Для показа клиенту используйте локальный запуск (раздел 9) — там всё работает
> с постоянным хранилищем.

`PUBLIC_BASE_URL` на Vercel задавать не обязательно: адрес сайта подставляется автоматически
(`VERCEL_PROJECT_PRODUCTION_URL`), поэтому Open Graph, sitemap и canonical сразу указывают на ваш домен.
Свой домен — задайте `PUBLIC_BASE_URL` вручную, например `https://kerey.kz`.

**Важно про персональные данные.** В файловом хранилище они лежат в `data/bookings.json` (файл исключён
из git), в Redis — в ключе `kerey:bookings:v1`. При передаче проекта третьим лицам или перед демонстрацией
посторонним выполните `npm run reset` (файловое хранилище) либо удалите ключ в Redis.

## 9. Показ клиенту (демо)

```bash
npm run demo
```

Скрипт сам очищает заявки, собирает свежую версию, поднимает сервер и печатает адрес для телефона
(если телефон клиента в той же сети Wi-Fi, он открывает сайт на своём телефоне) и пароль панели.

Сценарий показа на 5 минут:

1. Первый экран: рейтинг 4.9, 201 оценка, 132 отзыва, часы работы, адрес — всё из карточки 2ГИС.
2. Прокрутить страницу: услуги, «как записаться», отзывы (там же две честные оценки 1★ — это плюс),
   35 марок, вопросы, карта и маршрут.
3. Нажать «Записаться онлайн» и пройти 5 шагов — примерно 40 секунд.
4. Открыть `/admin` — заявка уже в списке. Показать смену статуса и кнопки «Позвонить» и «WhatsApp».
5. Раздел «Услуги»: названия, цены и длительность правятся владельцем без программиста.

Пароль панели: в демонстрационном режиме (без базы) — `demo`, в рабочем — значение `ADMIN_PASSWORD`.
Перед показом посторонним людям полезно выполнить `npm run reset`: это удаляет заявки с данными клиентов.
