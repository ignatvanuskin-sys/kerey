## 2. Цели и метрики

1. Посетитель с телефона оформляет запись за **≤ 90 секунд** и ≤ 4 шагов.
2. Владелец получает **карточку клиента в Telegram за ≤ 5 секунд** и обрабатывает её в 1 тап (подтвердить / отклонить).
3. **Нет двойных броней** даже при одновременных запросах.
4. Владелец сам правит услуги, график, выходные, число постов — без разработчика.
5. Заявка не теряется никогда: сначала запись в БД, потом уведомление; при сбое Telegram — повторные попытки и видимый статус в админке.
6. Сайт быстрый и находимый: Lighthouse mobile ≥ 90 по всем четырём категориям, локальное SEO (Кокшетау).

## 6. Онлайн-запись

### 6.1. Смысл записи
Запись — это запись **на приём** (осмотр/диагностика/работы) на слот длительностью `service.duration_min`. Для больших ремонтов это время приёма-осмотра, а не всего ремонта (иначе пост блокировался бы на дни). Это написать в описании услуги.

### 6.2. UX формы (bottom sheet на мобильном, dialog на десктопе + та же форма на `/zapis`)
Прогресс-бар, залипающая кнопка «Далее», возврат назад без потери данных, черновик в `sessionStorage`.

1. **Услуга:** карточки/чипы; опция «Не знаю — нужна диагностика». Предвыбор через `?service=slug`.
2. **Автомобиль:** марка (combobox: 35 марок из DATA + свободный ввод любой другой), модель (текст, обязательно), год (необязательно), гос. номер (необязательно).
3. **Дата и время:**
   - горизонтальный скроллер дат (по умолчанию `horizon_days = 21`), дни без свободных слотов приглушены и недоступны;
   - слоты чипами по группам «Утро / День / Вечер»; занятые — disabled; сегодня — только будущие с учётом `min_lead_min` (по умолчанию 60);
   - если часовой пояс устройства отличается от Кокшетау — подпись «Время указано по Кокшетау».
4. **Контакты:** имя, телефон (маска `+7 (___) ___-__-__`, принимать `8…`, `7…`, `+7…`, нормализовать в E.164), предпочтительная связь (звонок / WhatsApp / Telegram), комментарий (≤ 500), **обязательный чекбокс согласия** на обработку персональных данных со ссылкой на `/privacy`.

Отправка: блокировать кнопку, показывать loading, `Idempotency-Key` (UUID, генерируется на клиенте) — защита от дублей при повторе.

### 6.3. Экран успеха
Крупная галочка, «Запись №0042 отправлена мастеру», карточка-резюме (услуга, авто, дата/время, адрес), текст «Мы подтвердим запись по телефону или в WhatsApp», кнопки: «Добавить в календарь» (.ics, клиентская генерация), «Изменить или отменить» (ссылка `/booking/[token]`), «Позвонить». Персональная ссылка `/booking/[token]`.

### 6.4. Страница `/booking/[token]`
Публично по секретному токену (UUID v4), минимум данных: статус, услуга, дата/время, имя (без телефона). Статус обновляется опросом каждые 30 с: «Ожидает подтверждения» → «Подтверждена ✅» / «Отклонена — свяжемся для другого времени». Кнопка «Отменить запись» (подтверждение → статус `cancelled_by_client`, слот освобождается, владельцу уходит уведомление в Telegram). Перенос = отмена + новая запись (с предзаполненными данными).

### 6.5. Логика слотов (`lib/availability.ts`, покрыть Vitest)
```
getSlots(localDate, service):
  if localDate in days_off (полный выходной) → []
  hours = schedule[weekday] (учесть частичные days_off: open_from/open_to)
  for start = hours.open; start + service.duration_min <= hours.close; start += settings.slot_step_min (30):
      skip if start < now + settings.min_lead_min
      busy = count(bookings where status IN ('new','confirmed') AND b.start_at < slot_end + buffer AND b.end_at + buffer > slot_start)
      available = busy < settings.posts_count       // по умолчанию 2 (допущение, правится в админке)
```
- Занимают слот статусы `new` и `confirmed`. `rejected`, `cancelled_*`, `no_show`, `done` слот освобождают.
- **Атомарность:** создание брони — в транзакции с блокировкой на день (строка `day_locks(local_date)` + `SELECT … FOR UPDATE` / advisory lock; для SQLite — `BEGIN IMMEDIATE`): пересчитать доступность → вставить → коммит. Конфликт → HTTP 409 + свежий список слотов; UI: «Это время только что заняли, выберите другое».
- Граничные случаи покрыть тестами: последний слот до закрытия, слот через полночь (недопустим), выходной, частичный выходной, `posts_count = 1/2/3`, услуги разной длительности, смена суток по `Asia/Almaty`.

### 6.5.1. Статусы брони
```
new → confirmed | rejected | cancelled_by_client
confirmed → done | no_show | cancelled_by_owner | cancelled_by_client
```
Терминальные: `rejected, done, no_show, cancelled_*`. Любое изменение статуса идемпотентно (повторное нажатие не ломает состояние).

## 7. Telegram: карточка клиента владельцу

### 7.1. Принцип
Бот уже принадлежит владельцу (создаётся через @BotFather). Сайт шлёт карточки через Bot API с серверной части. Получатели — список `TELEGRAM_CHAT_IDS` (личный чат владельца и/или группа/второй админ).

### 7.2. Надёжность (outbox)
1. `POST /api/bookings` → запись в БД → в той же транзакции строка в `notifications` (`status=pending`).
2. Сразу пробуем отправить (fire-and-await с таймаутом 5 с); успех → `sent`, сохранить `message_id` для каждого чата.
3. Ошибка → `attempts++`, экспоненциальный backoff (1, 2, 5, 15, 60 мин, до 8 попыток), обработчик `/api/cron/notify` (защита `CRON_SECRET`; запускать планировщиком платформы каждые 1–5 мин) или внутрипроцессный воркер, если сервер долгоживущий.
4. Клиент **всегда** видит успех, если запись сохранена. Проблемы с Telegram — только в админке: бейдж «Telegram не доставлен» + кнопка «Отправить повторно».
5. Учитывать 429 (`retry_after`) и лимит 4096 символов (обрезать комментарий до 500).

### 7.3. Формат карточки (`parse_mode=HTML`, **весь пользовательский ввод экранировать**: `&`, `<`, `>`)
```
🆕 <b>Новая запись №0042</b>

🔧 <b>Услуга:</b> Компьютерная диагностика
🚗 <b>Авто:</b> Toyota Camry, 2012 · 123ABC02
📅 <b>Когда:</b> пт, 26 сентября · 14:30 (≈ 1 ч)
👤 <b>Клиент:</b> Асхат
📞 <b>Телефон:</b> +7 701 123 45 67
💬 <b>Связь:</b> WhatsApp
📝 <b>Комментарий:</b> стук спереди справа
🌐 <b>Источник:</b> сайт (2gis)
🕒 <b>Создана:</b> 21.09 12:05
```
Inline-кнопки под карточкой (только `https://` и `callback_data`; схема `tel:` в кнопках Telegram **не поддерживается** — номер клиента выводим в тексте, Telegram делает его кликабельным):
- Ряд 1: `✅ Подтвердить` · `❌ Отклонить`
- Ряд 2: `💬 WhatsApp клиенту` (URL `https://wa.me/<цифры номера>?text=<готовый текст>`) · `🛠 Открыть в админке`

Готовый текст для WhatsApp после подтверждения: «Здравствуйте, {имя}! Ваша запись в «Керей» на {дата} в {время} подтверждена. Адрес: ул. Шокана Уалиханова, 94, Кокшетау. Ждём вас!» — владельцу остаётся нажать «Отправить».

### 7.4. Обработка кнопок (webhook)
- `POST /api/telegram/webhook`: проверять заголовок `X-Telegram-Bot-Api-Secret-Token` == `TELEGRAM_WEBHOOK_SECRET`, иначе 401.
- `callback_data` формат: `bk:<id>:<action>`, `action ∈ ok | no | done | ns | cancel` (≤ 64 байт).
- **Авторизация:** обрабатывать нажатия только от `from.id` из `TELEGRAM_CHAT_IDS`; остальных — тихо игнорировать `answerCallbackQuery`.
- После действия: обновить статус в БД → `answerCallbackQuery` → `editMessageText` (шапка «✅ Подтверждена» / «❌ Отклонена» + кем и когда) → новая клавиатура:
  - `confirmed`: `✔️ Выполнено` · `🚫 Не приехал` · `↩️ Отменить` + `💬 WhatsApp клиенту` (с текстом подтверждения)
  - `rejected`/`done`/`no_show`/`cancelled`: без кнопок действия, оставить «Открыть в админке».
- Повторное нажатие — идемпотентно («Уже обработано»).
- `allowed_updates: ["message","callback_query"]`; скрипт `npm run tg:webhook` вызывает `setWebhook` с URL из `PUBLIC_BASE_URL` и secret.

### 7.5. Команды бота (только для whitelisted)
- `/start` — для чужих: «Ваш chat_id: N. Передайте его владельцу» (так владелец узнаёт свой ID при настройке); для владельца: краткая справка.
- `/today`, `/tomorrow` — список записей по времени (статус, услуга, авто, телефон).
- `/new` — необработанные (`status=new`).

### 7.6. Флаг совместимости
`TELEGRAM_CALLBACKS_ENABLED` (по умолчанию `true`). Если бот владельца уже работает в другом процессе (polling или свой webhook), **не вызывать `setWebhook`** — Telegram позволяет только один способ получения апдейтов. Тогда `false`: сайт только отправляет карточки (`sendMessage`) с URL-кнопками (WhatsApp, админка), а статусы меняются в админке. В README описать оба режима.

### 7.7. Опционально (только после того как всё основное работает)
- Ежедневный дайджест владельцу в 08:00 по Кокшетау («Записи на сегодня»).
- На странице успеха кнопка «Получать статус в Telegram» → `https://t.me/<BOT_USERNAME>?start=b_<token>`; при `/start b_<token>` привязать `chat_id` клиента к брони и присылать ему смену статуса.
- Кнопка «Прислать тестовое сообщение» в админке.

## 8. Админка (`/admin`)

Вход — один пароль владельца (`ADMIN_PASSWORD`, сравнение timing-safe), сессия — подписанный cookie `httpOnly; Secure; SameSite=Lax`, срок 7 дней, лимит 5 неудачных попыток / 15 мин / IP, `noindex`. Проверка `Origin` на всех мутациях.

Разделы:
1. **Записи:** вкладки «Сегодня / Завтра / Новые / Все»; фильтры (статус, дата, поиск по имени/телефону); карточка записи со сменой статуса; кнопки «WhatsApp клиенту», «Позвонить» (`tel:`), «Отправить в Telegram повторно»; бейдж состояния доставки в Telegram; **создание записи вручную** (звонок/визит — занимает слот); экспорт CSV.
2. **Услуги:** CRUD, порядок (drag or up/down), `is_active`, `duration_min`, `price_from`/`price_note`, иконка.
3. **График:** часы по дням недели, `posts_count`, `slot_step_min`, `buffer_min`, `min_lead_min`, `horizon_days`, **выходные и частичные выходные** с причиной (праздники, тех. работы).
4. **Контент:** контакты (переопределяют DATA), отзывы клиентов (добавить/скрыть), фото (загрузка, alt, порядок), тексты «Почему мы» (гарантия/опыт/оборудование — по желанию).
5. **Настройки:** тест Telegram, режим `TELEGRAM_CALLBACKS_ENABLED`, срок хранения персональных данных.

Админка должна быть удобна с телефона: владелец заходит по ссылке из Telegram.

## 10. Безопасность, антиспам, надёжность

- Zod-валидация на сервере (и на клиенте), лимиты длин, нормализация телефона (`lib/phone.ts`: KZ/RU `+7` + 10 цифр; `8XXXXXXXXXX` → `+7…`).
- Rate limit: `POST /api/bookings` — 5/час/IP и 3/сутки/телефон; логин админки — см. §8. Хранилище — БД или Redis (in-memory недостаточно на serverless).
- Антиспам: honeypot-поле, минимальное время заполнения формы (> 3 с), опционально Cloudflare Turnstile (`TURNSTILE_*`).
- Пользовательский ввод: в Telegram — экранирование HTML; в админке — без `dangerouslySetInnerHTML`.
- Заголовки: CSP (self + нужные домены карты/аналитики), `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'` для админки, HSTS на проде.
- Логи без персональных данных (телефон маскировать: `+7705***2164`).
- Публичные эндпоинты не раскрывают телефоны и чужие записи; токен брони — не угадываемый (UUID v4).
- Персональные данные: обязательное согласие, страница `/privacy` (типовая политика по закону РК «О персональных данных и их защите»; в отчёте пометить «проверить юристом»), возможность удалить запись в админке.
- Никаких секретов в репозитории; `.env.example` без значений.

## 12. Контент и правила «не выдумывать»

- Разрешено утверждать только то, что есть в DATA (§1) или введено владельцем в админке.

- **Seed услуг — черновик**, не подтверждён карточкой 2ГИС; владелец обязан проверить. Заложить как редактируемые записи (`slug`, длительность приёма в скобках):

  7. «Не знаю, что сломалось — диагностика» (60)
  Цены пустые → «по результатам диагностики».
- Тон текстов: коротко, по делу, на «вы», без крика и капса.

## 15. QA-чеклист / Definition of Done

Проект не считается готовым, пока не пройдено (отметь в отчёте PASS/FAIL по каждому пункту):

1. Запись с экрана 360 px проходит за ≤ 4 шага; карточка в Telegram приходит ≤ 5 с, все поля корректны.
2. `✅ Подтвердить` / `❌ Отклонить`: статус в БД меняется, карточка редактируется, при отклонении слот освобождается; повторное нажатие безопасно.
3. Два одновременных запроса на последний слот → один успех, второй 409 со свежими слотами.
4. Неверный токен бота → запись всё равно сохранена, клиент видит успех, в админке «Telegram не доставлен», ретраи идут, «Отправить повторно» работает.
5. Имя `<b>x</b> & <script>alert(1)</script>` не ломает разметку Telegram и не исполняется в админке.
6. Нажатие кнопок пользователем не из `TELEGRAM_CHAT_IDS` игнорируется; `/start` от чужого показывает только его `chat_id`.
7. Прошедшее время недоступно; `min_lead_min` соблюдён; выходные и частичные выходные учтены; последний слот заканчивается не позже закрытия; переход суток по `Asia/Almaty`.
8. Устройство в другой таймзоне (VPN) → слоты и время в карточке всё равно по Кокшетау.
9. Телефоны `8 705…`, `+7 705…`, `705…` нормализуются одинаково; мусор отклоняется.
10. Rate limit, honeypot и защита от повторной отправки (`Idempotency-Key`) работают.
11. `/booking/[token]`: статус обновляется после подтверждения владельцем; отмена клиентом освобождает слот и уведомляет владельца.
12. Пустые состояния: нет услуг / фото / отзывов → блоки скрыты, ничего не ломается.
13. В клиентском бандле и в репозитории нет секретов (`grep` по токену/паролю).
14. Lighthouse mobile ≥ 90 (Performance, Accessibility, Best Practices, SEO); навигация с клавиатуры; контраст AA.
15. JSON-LD валиден, `sitemap.xml` и `robots.txt` отдаются; `/admin` и `/booking` не индексируются.
16. Vitest на слоты зелёный.
